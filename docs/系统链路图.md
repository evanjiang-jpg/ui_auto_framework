## 二、测试执行主链路

```mermaid
flowchart TD
    A["python run.py -m smoke -n 4"] --> B{"参数解析<br/>argparse"}
    B --> C{"--list-envs / --list-markers?"}
    C -->|是| D["辅助动作后退出"]
    C -->|否| E{"--notify-only?"}
    E -->|是| F["读 allure-results → 解析结果 → 发通知 → 退出"]
    E -->|否| G["设置 ENV 环境变量<br/>加载 EnvManager"]

    G --> H["打印环境概览<br/>config.describe()"]
    H --> I{"--clean?"}
    I -->|是| J["清理 allure-results / allure-report"]
    I -->|否| K["构建 pytest 命令"]
    J --> K

    K --> L["subprocess.call<br/>python -m pytest ..."]

    subgraph "pytest 内部"
        L --> M["conftest 加载 4 个插件"]
        M --> N["plugin.options<br/>pytest_addoption / pytest_configure<br/>切换环境"]
        N --> O["plugin.hooks_tags<br/>pytest_collection_modifyitems<br/>数据驱动自动打标签"]
        O --> P["plugin.fixtures<br/>按 scope 实例化"]

        subgraph "fixture 实例化（scope 从宽到窄）"
            P --> P1["session: auth<br/>临时 driver 登录 → 关 driver → 留 token"]
            P --> P2["session: api_login<br/>读 --api-login 开关"]
            P --> P3["session: db<br/>sqlite 初始化 schema.sql"]
            P --> P4["function: browser<br/>create_driver + 注入登录态"]
            P --> P5["function: api_setup<br/>造用户/订单 + 后置清理"]
            P --> P6["function: db_assert<br/>DatabaseAsserter(db)"]
            P --> P7["function: clean_context<br/>autouse → context.clear"]
        end

        P1 & P2 --> P4
        P3 --> P6

        subgraph "用例执行循环"
            P4 & P5 & P6 --> Q["test_xxx(browser, api_setup, ...)"]
            Q --> R{"成功?"}
            R -->|是| S["写 allure-result.json"]
            R -->|否| T{"仍有重试机会?"}
            T -->|是| U["pytest-rerunfailures<br/>execution_count++"]
            T -->|否| V["plugin.hooks_screenshot<br/>pytest_runtest_makereport<br/>截图 + 页面源码 + 堆栈"]
            U --> Q
            S --> W["继续下一条"]
            V --> W
        end
    end

    W --> X["pytest 退出，回到 run.py"]
    X --> Y["parse_allure_results<br/>解析 allure-results/ 汇总"]
    Y --> Z["打印执行汇总"]
    Z --> AA["generate_report<br/>allure generate → allure-report/"]
    AA --> AB{"--no-report?"}
    AB -->|否| AC["allure serve<br/>阻塞等待 Ctrl+C"]
    AB -->|是| AD["跳过本地报告服务"]
    AC --> AE{"--notify?"}
    AD --> AE
    AE -->|是| AF["send_notification → TestNotifier.send()"]
    AE -->|否| AG["结束"]
    AF --> AG
```

**6 个阶段**：参数解析 → EnvManager 加载 → subprocess 调用 pytest → fixture 实例化（scope 从宽到窄）→ 用例循环 + 重试 + 截图 → 汇总报告 → 通知。

## 四、多环境配置加载链路

```mermaid
flowchart TD
    A["run.py -e dev<br/>或 ENV=dev"] --> B["EnvManager.__init__"]
    B --> C["1️⃣ _load_dotenv()<br/>读取 config/.env<br/>load_dotenv override=False"]
    C --> D["2️⃣ 读 environments.yaml<br/>分离 _meta 与业务配置"]
    D --> E["3️⃣ 确定当前环境<br/>显式参数 > ENV 变量 > local.yaml.__env__ > _meta.default_env"]
    E --> F["4️⃣ _read_local_overlay()<br/>读取 config/local.yaml（不入库）"]
    F --> G["5️⃣ reload()"]

    G --> H["合并顺序（深合并，后者覆盖前者）"]
    H --> H1["① default 层"]
    H1 --> H2["② 当前环境层<br/>（如 dev/test/staging/prod）"]
    H2 --> H3["③ local.yaml 覆盖层"]

    H3 --> I["_resolve_placeholders()<br/>递归替换 ${VAR} → os.getenv(VAR)"]
    I --> J["_validate()<br/>_meta.required_keys 校验<br/>缺失立刻报错"]
    J --> K["config._config 就绪"]

    subgraph "配置文件分层"
        direction LR
        DF["environments.yaml<br/>_meta + default + dev + test + staging + prod"]
        LY["local.yaml<br/>（不入库，个人覆盖）"]
        DV[".env<br/>密钥占位符注入"]
        DY["database.yaml<br/>（可被 load_layered_yaml 单独加载）"]
    end

    style A fill:#e3f2fd
    style J fill:#ffcdd2
    style K fill:#c8e6c9
```

**加载优先级**：显式参数 > ENV 环境变量 > `local.yaml.__env__` > `_meta.default_env`。三层深合并 + `${VAR}` 占位符递归替换，`_validate()` 缺失必需 key 立即报错防止静默失败。

## 六、通知系统链路

```mermaid
flowchart TD

    C --> D["补充 CI 元信息<br/>env / report_url / commit_author<br/>commit_msg / pipeline_id"]

    E --> F{"从环境变量<br/>判断启用哪些通道"}
    F --> |DINGTALK_ENABLED=true<br/>或 DINGTALK_WEBHOOK 存在| G["send_dingtalk<br/>Jinja2 模板渲染<br/>templates/dingtalk.md.j2<br/>→ POST webhook + 签名"]
    F --> |FEISHU_ENABLED=true<br/>或 FEISHU_WEBHOOK 存在| H["send_feishu<br/>Jinja2 模板渲染<br/>→ POST webhook + 签名"]
    F --> |EMAIL_ENABLED=true<br/>或 EMAIL_PASSWORD 存在| I["send_email<br/>Jinja2 模板渲染<br/>templates/email.html.j2<br/>+ templates/email.txt.j2<br/>→ SMTP 发送"]

    G & H & I --> J{"单通道异常?"}
    J -->|是| K["logger.error 记录<br/>不影响其它通道"]
    J -->|否| L["results[channel] = True"]

    K & L --> M["返回 Dict[str, bool]<br/>汇总各通道发送结果"]

    subgraph "数据流向（与 pytest 解耦）"
        AR["allure-results/<br/>JSON 原始结果"] --> B
    end

    subgraph "安全设计"
        ENV_VAR["DINGTALK_WEBHOOK<br/>FEISHU_SECRET<br/>EMAIL_PASSWORD<br/>→ 全部走环境变量<br/>不进仓库"]
    end

    style A fill:#e3f2fd
    style M fill:#c8e6c9
    style ENV_VAR fill:#ffcdd2
```

**设计要点**：从 `allure-results` 反解析（与 pytest 完全解耦），三个通道独立 try/except 互不影响，密钥全部走环境变量。

## 七、浏览器与接口的双轨设计

```mermaid
graph TD
    subgraph "演示/无后端模式（默认）"
        direction LR
        S1["use_stub_browser: true"] --> SD["StubDriver<br/>内置桩驱动<br/>无需真实浏览器"]

    end

    subgraph "真实项目模式"
        direction LR

    subgraph "登录态注入（两种方式）"
        direction TB
        UI_LOGIN["--api-login 未启用<br/>session auth fixture<br/>临时 driver 走登录页<br/>拿到 token → BasePage.inject_token<br/>注入 localStorage"]
        API_LOGIN_FLAG["--api-login 启用<br/>api_client.login_by_api()<br/>直接 POST /api/login<br/>拿到 cookies → inject_auth_to_browser<br/>selenium.add_cookie 注入"]

    API_LOGIN_FLAG -->|"跳过 UI 登录页<br/>快 3-5 倍"| SEL

    style MA fill:#fff9c4
    style SEL fill:#c8e6c9
    style REAL fill:#c8e6c9
```

**双轨灵活切换**：`stub_driver + mock_api` 让项目开箱即跑，`selenium + requests` 对接真实后端。登录态也有 UI/API 双通道，API 登录快 3-5 倍。

## 架构设计原则总结

| 原则 | 体现 |
|------|------|
| **单一入口** | `run.py` 统一 argparse → subprocess pytest，CI 和本地都走它 |
| **插件化** | conftest 只做 `pytest_plugins = [...]`，每个 plugin 文件独立职责 |
| **分层配置** | `environments.yaml` 多环境 + `local.yaml` 个人覆盖 + `.env` 密钥 |
| **scope 安全** | fixture 严格 session → function 单向依赖 |
| **解耦通知** | 从 allure-results 反解析，与 pytest 执行完全解耦 |
| **通道隔离** | 三个通知通道独立 try/except，互不影响 |
| **双轨运行** | StubDriver + mock_api 让无后端也能跑 |
| **GitHub/GitLab 双流水线** | Dockerfile 共享，各自适配 Runner 网络环境 |
