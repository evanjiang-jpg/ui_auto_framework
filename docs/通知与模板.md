# 通知与模板

执行结束后自动把结果推送到钉钉群与邮箱，让团队第一时间知道结果，不用登录 CI 平台翻记录。

---

## 一、模块结构

通知模块按职责拆成四层，改动互不影响：

```
common/notifier/
├── models.py            # 结果数据模型 + 解析 allure-results
├── templates.py         # 模板定位与渲染 + 统一上下文
├── channels/
│   ├── dingtalk.py      # 钉钉通道（Markdown + 加签 + @人）
│   └── email.py         # 邮件通道（HTML + 纯文本 + 报告附件）
├── notifier.py          # 门面：读配置 → 调度通道 → 汇总
└── templates/           # 内置模板（未自定义时的兜底外观）
```

**通道解耦**：钉钉和邮件各自独立开关，任一通道异常都不影响另一通道，更不影响用例执行结果。

**结果来源**：直接解析 `allure-results/*-result.json`，不依赖 pytest 内部钩子，
因此在本地、GitLab、Jenkins、GitHub Actions 上表现完全一致。

## 二、配置

复制 `config/.env.example` 为 `config/.env`，按需填写：

### 钉钉群机器人

```ini
DINGTALK_ENABLED=true
DINGTALK_WEBHOOK=https://oapi.dingtalk.com/robot/send?access_token=xxx
DINGTALK_SECRET=SECxxx                # 安全设置选「加签」时必填
DINGTALK_AT_MOBILES=13800138000,13900139000
DINGTALK_AT_ALL=false
```

### 邮件

```ini
EMAIL_ENABLED=true
EMAIL_SMTP_HOST=smtp.example.com
EMAIL_SMTP_PORT=465
EMAIL_SMTP_SSL=true
EMAIL_USER=auto_test@example.com
EMAIL_PASSWORD=xxxxxx                 # 邮箱授权码，不是登录密码
EMAIL_SENDER=auto_test@example.com
EMAIL_RECEIVERS=tester1@example.com,tester2@example.com
EMAIL_CC=leader@example.com
```

> 敏感值在 CI 上请配置为平台的加密变量，不要写进仓库。

## 三、使用

```bash
python run.py --notify                              # 跑完发通知
python run.py -m smoke -n 4 --no-report --notify    # CI 常用组合
```

CI 环境下会自动把 `CI_PIPELINE_ID`、`CI_COMMIT_AUTHOR`、`CI_COMMIT_MSG`、`CI_BUILD_URL`
带进消息，点击链接可直达流水线构建页。

---

## 四、通知内容

**钉钉（Markdown）**：执行结果、环境、统计表格（总数/通过/失败/异常/跳过/通过率/耗时）、
失败用例清单、报告链接、@指定人。

**邮件（HTML + 纯文本双模板）**：渐变头部、统计卡片、彩色通过率、失败用例表格、
报告按钮；纯文本副本兼容老旧客户端；自动把 Allure 报告打包为 zip 附件
（超过 20MB 自动跳过附加）。

## 五、自定义模板

通知内容用 Jinja2 渲染，**三级查找 + 内置兜底**，改模板不需要动代码。

### 优先级

```
1. 自定义目录     templates/notify/  或  环境变量 NOTIFY_TEMPLATE_DIR 指定的目录
2. 内置模板目录   common/notifier/templates/
3. 代码内置字符串 模板文件被删或写坏时的最后一道保险
```

自定义目录里没有对应模板时，会自动继续找内置模板；全部找不到或渲染报错时，
降级到代码内置字符串——**保证任何情况下通知都能发出去，只是外观退化**。

### 三个可自定义模板

| 文件 | 用途 |
|---|---|
| `dingtalk.md.j2` | 钉钉 Markdown 消息 |
| `email.html.j2` | 邮件 HTML 正文 |
| `email.txt.j2` | 邮件纯文本正文 |

```bash
# 把内置模板复制出来改
cp common/notifier/templates/*.j2 templates/notify/
```

改完直接生效，不需要重启任何服务。

### 可用变量（所有模板共享同一份上下文）

| 分类 | 变量 |
|---|---|
| 基础信息 | `env` `branch` `author` `commit_msg` `pipeline_id` `pipeline_url` `trigger_type` `executed_at` |
| 执行结果 | `is_success` `status_text` `total` `passed` `failed` `broken` `skipped` `retried_success` `pass_rate` `duration` |
| 失败详情 | `failed_cases`（列表，每项含 `name` `message` `status`） |
| 链接 | `report_url` `report_path` |
| @ 配置 | `at_mobiles` `at_all` |

### 示例：自定义钉钉模板

```jinja
## {% if is_success %}✅{% else %}❌{% endif %} {{ env | upper }} 环境测试结果

通过率 **{{ pass_rate }}%**（{{ passed }}/{{ total }}），耗时 {{ duration }}s

{% for case in failed_cases %}
- {{ case.name }}
{% endfor %}

[查看报告]({{ report_url }})
```

## 六、本地预览（不发真实通知）

```bash
python scripts/preview_notify.py          # 用假数据渲染并打印通知内容
```
